# 設計メモ

要件定義書の判断を、実装のどこでどう守っているかの対応表。

## 1. 「正解手は AI エンジンだけが決める」の担保

要件 2.3 の最大リスク。誤った正解手を教える学習アプリは、学習しないより有害。

| 決めごと | 実装 |
|---|---|
| 勝率・最善手・候補手は KataGo の出力そのまま | `katago.py` の `TurnAnalysis` / `MoveInfo` |
| 呼吸点・連・取り上げは自前の盤面計算 | `goban.py`（LLM を通さない） |
| Claude に渡すのは数値だけ | `explain.py` の `MoveContext.to_prompt()` |
| Claude の出力はタグ語彙で検証 | `explain.suggest_tags()` が付録B の語彙外を捨てる |
| API が使えないときは数値の言い換えだけ | `explain.template_explanation()` |
| スタブエンジン使用時は問題を作らない | `analysis.analyze_game()` が `stub` を見て抑止 |

勝率の視点は KataGo への問い合わせごとに `overrideSettings` で `BLACK` に固定して
いる。設定ファイルの差異で符号が反転すると、悪手と好手が入れ替わるため。

## 2. 中断耐性（Windows Update 対策）

- `db.save_move()` は1手ごとに `commit()` する
- 再開時は `analyzed_move_numbers()` で解析済みの turn を逆算し、足りない分だけ解析する
- 局面は `analysis_cache` にハッシュキーで保存し、再解析しない
- 1回の実行は `MAX_RUNTIME_MINUTES`（既定120分）で打ち切り、状態は `解析中` のまま残す

## 3. 2パス方式

| パス | 対象 | visits | 目的 |
|---|---|---|---|
| 1 | 全手 | 150 | 勝率の大きな落差の検出 |
| 2 | 悪手候補の前後の局面のみ | 1,500 | 正解手の確定と変化図の生成 |

1局110手なら、1パス目は111局面、2パス目は最大6局面。全手を高 visits で
解析するのに比べて計算量が大きく下がる。

## 4. タグ判定の考え方

`tagging.py` の判定はいずれも経験則。誤検出を減らすため「盤面から確実に
言えること」に寄せてある。

| タグ | 判定 |
|---|---|
| アタリ見落とし | 着手後に2子以上の自分の連が呼吸点1になった／相手の最善の咎め手でそうなる |
| 切断された | 相手の咎め手が自分の異なる2連に接している |
| 攻め合い負け | 隣接する敵味方の連で、呼吸点の優劣が逆転した |
| 眼形不足 | ownership が生（>0.3）から死（<-0.3）へ転じた石群がある |
| 大場放置 | 最善手と実際の着手のチェビシェフ距離が4以上 |
| ヨセ損 | 残り20手以内で目数換算3目以上の損 |

手筋名（シチョウ・ゲタ等）と方針レベルの分類だけ Claude が補完する。

## 5. 勝率の視点

DB には「その手を打った側から見た勝率」を保存し、配信時に自分視点へ揃える
（`export._my_winrate`）。相手の手のあとの勝率は 100 から引く。画面では
黒白で反転させない（FR-07）。

## 6. 学習効果のためのUI制約

| 要件 | 実装 |
|---|---|
| 回答前に AI 評価・正解手を出さない（FR-09） | 出題画面は盤面のみ。判定後に初めて候補手を重ねる |
| 自己診断 → AI答え合わせ の順序を強制（US-07） | 棋譜画面のゲート。記録するかスキップを明示するまで勝率グラフ・マーカー・解説を出さない |
| 好手マーカーを乱発しない（FR-07） | `badmoves.good_move_markers()` が「候補が拮抗する局面で上位手」か「明確な勝率上昇」に限定 |
| 1局最大3問・1日10問 | `problem_candidates()` と `due_problems()` |
| ヒントで正解手を明示しない | `problems.build_hints()` は着眼点・領域・タグまで |
| 催促しない | 詰碁の未入力日は空欄のまま。通知は出さない |

## 7. データの置き場所

- コード: このリポジトリ（OneDrive 配下でも問題ない）
- 実行時データ: 既定で `%LOCALAPPDATA%\go-review`（**OneDrive の外**）

SQLite を同期フォルダに置くと衝突コピーが生まれ、マスタが壊れる。
`GOREVIEW_DATA_DIR` で変更できる。

## 8. 費用0円の維持

| 要素 | 費用 |
|---|---|
| 解析（KataGo） | 電気代のみ |
| 配信 | GitHub Pages / Cloudflare Pages の無料枠。静的ファイルのみ |
| Notion API | 無料 |
| Claude API | 1局あたり数円。キー未設定ならテンプレート生成に自動で切り替わる |

外部パッケージを増やしていないのは、費用というより**空き容量と導入の手間**の
問題。Notion API は urllib で十分に呼べる。

## 9. 既知の割り切り

- **コウの厳密な再現はしない。** 実戦譜の再生と局面復元が目的で、合法手生成器ではない
- **ownership の並び順**は「左上起点の行優先・黒が正」と仮定している。眼形不足タグが
  不自然なら、まずここを疑う（`tagging._ownership_at`）
- **検討モードは自宅Wi-Fi・解析機起動中のみ。** 外出先ではグレーアウトする
- **PWA からの学習ログ送信先**は解析機のローカルサーバを既定にしている。外出先からも
  送りたい場合は `GOREVIEW_CONFIG.apiBase` に無料枠のプロキシを立てる必要がある。
  送れないあいだは IndexedDB に保持し、復帰時に自動送信する
