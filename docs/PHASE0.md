# Phase 0: Notion DB の整備と棋譜移行

このフェーズでは解析を一切行わない。データの入り口だけを固める。

## Notion API のバージョンについて

本実装は `Notion-Version: 2025-09-03` を使う。このバージョンでデータベースは
1つ以上の「データソース」を格納するコンテナになり、プロパティとページは
データソース側に属する。

| 操作 | 本実装での呼び出し |
|---|---|
| 行の取得 | `POST /v1/data_sources/{data_source_id}/query` |
| ページ作成 | `POST /v1/pages` / parent は `{"type":"data_source_id","data_source_id":...}` |

`databases.query` は使わない（このバージョンでは使えない）。
データベースIDとデータソースIDは別物で、互いに置き換えて使うことはできない。

## Step 1. インテグレーション

1. https://www.notion.so/my-integrations で内部インテグレーションを作る（名前: `go-review-app`）
2. 機能は **コンテンツの読み取り / 更新 / 挿入** を有効化。ユーザー情報の読み取りは不要
3. 発行された Internal Integration Secret を `.env` の `NOTION_TOKEN` へ

トークンは絶対にリポジトリへコミットしない（`.gitignore` に `.env` を入れてある）。

## Step 2. 棋譜DB（受信箱）

名前: `囲碁 棋譜DB`。フルページで作成する。**ユーザーが入力するプロパティは1つもない。**

| プロパティ名 | 型 | 選択肢 |
|---|---|---|
| 名前 | タイトル | — |
| 対局日 | 日付 | — |
| 自分の色 | セレクト | 黒 / 白 |
| 相手名 | テキスト | — |
| 相手レーティング | 数値 | — |
| 結果 | セレクト | 勝 / 負 / 引分 |
| 目数差 | 数値 | — |
| 総手数 | 数値 | — |
| 終局種別 | セレクト | 終局 / 投了 / 時間切れ |
| 解析ステータス | セレクト | 未解析 / 解析済 / 要確認 |
| 敗着手数 | 数値 | — |
| 主要タグ | マルチセレクト | （付録B のタグ体系） |
| レビューURL | URL | — |

プロパティ名は**1文字でも違うと `validation_error`** になる。全角・半角に注意。
実装側の定義は `go_review/ingest.py` の先頭にまとめてある。

SGF 用のプロパティは作らない。共有時に SGF 本文はページ本文に入るため、
アプリが本文ブロックを読む。

ビュー: 「未解析」（解析ステータス = 未解析 または 空）／「要確認」／「全対局」。

## Step 3. 学習ログDB

名前: `囲碁 学習ログDB`。

| プロパティ名 | 型 | 入力者 |
|---|---|---|
| 日付 | 日付 | アプリ |
| 対局数 / 詰碁解答数 / 詰碁誤答数 / 問題正答率 | 数値 | アプリ |
| 最頻タグ | マルチセレクト | アプリ |
| 気づき | テキスト | **本人**（任意・1行） |

「気づき」だけが双方向同期の対象。外出先でスマホから書いた内容を取り込む。

## Step 4. 接続とID取得

各DBの `…` → 接続 → `go-review-app` を追加する。**この2つのDBだけに接続する。**
親ページに接続すると配下すべてが読めてしまい、最小権限にならない。
旧DBは移行のあいだだけ一時的に接続し、完了後に解除する。

データベースIDは URL の32桁。データソースIDは次で取得できる。

```powershell
python scripts/notion_ids.py <DATABASE_ID>
```

`.env` に5つ揃える: `NOTION_TOKEN` / `KIFU_DS_ID` / `LOG_DS_ID` / `OLD_DS_ID` / `KIFU_DB_ID`。

## Step 5. 移行

```powershell
python scripts/migrate_notion.py            # dry-run（既定）
python scripts/migrate_notion.py --execute  # 実行
```

スクリプトの性質:

- 既定は dry-run。`--execute` を明示しない限り一切書き込まない
- 移行元のページは**読むだけ**。削除も編集もしない
- 処理済みハッシュを `processed.json` に逐次追記し、再実行は続きから
- 各リクエスト間に 0.4 秒待機（Notion API は概ね毎秒3リクエストが上限）
- `has_more` / `next_cursor` を必ず処理する（100件で打ち切らない）
- ページ本文は**全ブロックを連結してから** SGF を抽出する
- 1ページで例外が出ても全体を止めず、スキップして続行する
- SGF 本文は 2,000 文字未満のブロックに分割して投入する

## Step 6. 共有先の切り替えと検証

1. スマホの Notion アプリで新しい棋譜DBを一度開く（共有シートの候補に出やすくなる）
2. 囲碁クエストで1局打ち、「棋譜を共有」→ Notion → **新DB** を選ぶ
3. 本文に SGF が入っていることを確認する
4. 3〜5日、通常どおり運用する

チェックリスト:

- [ ] 共有したページが必ず新DBに入っている
- [ ] SGF 本文が途中で切れていない
- [ ] 1日に複数局共有しても重複や取りこぼしがない
- [ ] 移行スクリプトを再実行しても二重登録が起きない

旧DBは当面残す。共有先を間違えたときの受け皿として、`sync` は旧DBも監視し、
棋譜を見つけたら取り込んだうえで「旧DBに追加されています」とログに出す。

## つまずきやすい点

| 症状 | 原因と対処 |
|---|---|
| `object_not_found` | そのDBにインテグレーションを接続していない |
| `Databases with multiple data sources are not supported` | 旧エンドポイントを叩いている。データソース用に変更する |
| データソースIDを入れたのに動かない | データベースIDと取り違えている。両者は互換性がない |
| `validation_error`（プロパティ名） | Notion 側の名前と実装側の文字列が違う。全角・半角に注意 |
| SGF が途中で切れる | 本文が複数ブロックに分割されている。全ブロックを連結してから抽出する |
| 429 が頻発 | スリープが足りない。`notion.py` の `RATE_LIMIT_SLEEP` を増やす |

## 完了条件

- [ ] 新DB2つが作成され、プロパティ定義どおりになっている
- [ ] インテグレーションが2つのDBにのみ接続されている
- [ ] `.env` が用意され、`.gitignore` に含まれている
- [ ] 移行スクリプトが dry-run で正しい件数を報告する
- [ ] `--execute` で移行が完了し、二重登録がない
- [ ] 共有先を新DBに切り替え、3〜5日の運用で取りこぼしがない

ここまで完了したら Phase 1（KataGo による解析）へ進む。
